# 3-billing-wallet-invoices — UI: wallet + invoice-pay

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).
> Apply the **fix-and-retest gate** when any case fails.

**Surface(s) under test:**
- `app/dashboard/organization/[orgId]/billing/page.tsx` — invoice list + payment button
- `app/dashboard/organization/[orgId]/billing/WalletTab.tsx` — wallet balance + top-up entry
- `app/dashboard/organization/[orgId]/credits/page.tsx` — legacy alias, polls status
- Razorpay popup (rendered by `@razorpay/checkout-js`)

**Case roster:**
1. **UI.W.1** — Open wallet, click "Top up", Razorpay popup renders
2. **UI.W.2** — Pay test card → "Awaiting confirmation" toast → "Top-up confirmed" after webhook
3. **UI.W.3** — Pay test card with `payment.failed` → toast surfaces failure
4. **UI.W.4** — Dismiss popup → balance unchanged
5. **UI.W.5** — Open invoice, click "Pay", popup renders for invoice amount
6. **UI.W.6** — Invoice flips to PAID after webhook + UI re-renders status pill

---

## Case UI.W.1: Open wallet → Razorpay popup

Login as Wipro OWNER. Navigate to `/dashboard/organization/<wipro-id>/billing`.

`take_snapshot`. Click "Top up wallet" → modal/popup opens.

`take_snapshot` again. The Razorpay popup iframe should be visible.

`list_network_requests` should show a POST to `/wallet/top-ups`
returning 201 with an `orderId`.

---

## Case UI.W.2: Successful top-up

Enter test card `4111 1111 1111 1111`, OTP `1234` in the Razorpay popup.

Bounded polling kicks in (see `app/dashboard/organization/[orgId]/credits/page.tsx`).

Expected sequence:
1. Toast: "Processing top-up" or "Awaiting confirmation."
2. Within ~10s, webhook lands, polling returns `confirmed`.
3. Toast flips to "Top-up confirmed."
4. Wallet balance UI refreshes (+₹5000 = +500000 paise).

DB confirmation per `3.1-api-wallet-top-up-and-invoices.md` case W.2.

---

## Case UI.W.3: Failure path

Use a Razorpay failure-card test:
```
Card: 5104 0600 0000 0008 (Mastercard, test failure)
```

Expected:
- Popup surfaces "Payment failed" inline.
- Toast: "Payment failed. Please try again."
- Wallet balance UNCHANGED.
- DB: WalletEntry remains pending or is marked FAILED.

---

## Case UI.W.4: Dismissed popup

Open the popup, close it (X button). Expected:
- No toast (silent dismissal contract).
- Wallet balance unchanged.
- WalletEntry created but never confirmed (pending forever — Razorpay
  cleans up its side; our row remains until a sweeper cron handles it).

---

## Case UI.W.5: Invoice pay popup

Open `/billing`. Click the "Pay" button on an ISSUED invoice.

Razorpay popup renders with the invoice amount (not the wallet flow).

`list_network_requests` shows POST `/invoices/<id>/pay` returning 200
with `orderId`.

---

## Case UI.W.6: Invoice paid → status pill updates

Complete the popup with test card 4111-1111. Expected:
- Toast: "Invoice paid."
- Status pill on the invoice row flips from ISSUED → PAID without page
  reload (React Query invalidates the invoice cache, or polling does
  the same).
- DB matches case W.8 in the API file.
