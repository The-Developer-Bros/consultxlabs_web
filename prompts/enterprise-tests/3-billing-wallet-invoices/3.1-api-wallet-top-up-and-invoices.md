# 3-billing-wallet-invoices — API: wallet top-up + invoices

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).
> Apply the **fix-and-retest gate** when any case fails.

**Surface(s) under test:**
- `app/api/organizations/[orgId]/billing-account/wallet/top-ups/route.ts` — POST (mint Razorpay order)
- `app/api/organizations/[orgId]/billing-account/wallet/top-ups/[topUpId]/route.ts` — GET (status poll)
- `app/api/organizations/[orgId]/billing-account/invoices/route.ts` — POST (issue manual)
- `app/api/organizations/[orgId]/billing-account/invoices/[invoiceId]/route.ts` — PATCH (status transitions)
- `app/api/organizations/[orgId]/billing-account/invoices/[invoiceId]/pay/route.ts` — POST (mint payment order)
- `app/api/webhooks/razorpay/route.ts` — webhook handler (flips status to PAID)

**Case roster:**
1. **W.1** — Wallet top-up POST (happy: mints Razorpay order + pending WalletEntry)
2. **W.2** — Top-up status polling (`pending` → `confirmed` via webhook)
3. **W.3** — Webhook idempotency (replay same payload → no double-credit)
4. **W.4** — Razorpay not configured → 503
5. **W.5** — Invoice POST (manual issue, GST breakdown computed)
6. **W.6** — Invoice PATCH allow-list (status transitions guarded)
7. **W.7** — Invoice /pay (mints Razorpay order for invoice payment)
8. **W.8** — Webhook flips invoice ISSUED → PAID, writes SettlementLedgerEntry

## Case W.1: Wallet top-up POST

Switch funding source to WALLET first:
```sql
UPDATE "BillingAccount" SET "fundingSource" = 'WALLET' WHERE id = '<baId>';
```

```js
() => fetch("/api/organizations/<wipro-id>/billing-account/wallet/top-ups", {
  method: "POST", credentials: "include",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({ amountPaise: 500000 })
}).then(async r => ({ status: r.status, body: await r.json() }))
```

### Assertions
- `status === 201`
- `body.data.orderId` is a Razorpay order id (string prefix `order_`).
- `body.data.publishableKey === process.env.RAZORPAY_KEY_ID`.
- `WalletEntry` row exists: `deltaPaise = 500000`, `reason = 'TOPUP'`, `providerOrderId = <orderId>`, status indicating pending.
- Audit: `WALLET_TOPUP`.

## Case W.3: Webhook idempotency

Forge the Razorpay webhook payload (signed with `RAZORPAY_WEBHOOK_SECRET`):
```bash
curl -X POST http://localhost:3000/api/webhooks/razorpay \
  -H "Content-Type: application/json" \
  -H "X-Razorpay-Signature: <hmac-sha256-of-body>" \
  -d '{
    "event": "payment.captured",
    "payload": {
      "payment": {
        "entity": {
          "id": "pay_test123",
          "order_id": "<orderId>",
          "amount": 500000,
          "notes": { "type": "credit_purchase", "organizationId": "<wipro-id>" }
        }
      }
    }
  }'
```

Run **twice**. Both should return 200. DB state after both: exactly one
confirmed WalletEntry, `walletBalance += 500000` (not +1000000).

The webhook handler dedups on `WalletEntry.providerOrderId @unique`.

## Case W.5: Invoice POST

```js
() => fetch("/api/organizations/<wipro-id>/billing-account/invoices", {
  method: "POST", credentials: "include",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({
    contractId: "<contractId>",
    issueImmediately: true,
    displayCurrency: "INR",
    dueDate: new Date(Date.now() + 30 * 86400 * 1000).toISOString(),
    items: [{ description: "test W.5", quantity: 1, unitPrice: 100000 }]
  })
}).then(async r => ({ status: r.status, body: await r.json() }))
```

### Assertions
- `status === 201`
- `body.data.invoiceNumber` matches `<PREFIX>-<FY>-<SEQ>` (see
  `3.3-per-org-invoice-numbering.md` for details).
- `igstPaise > 0` or `cgstPaise+sgstPaise > 0` depending on
  buyer/supplier state.
- Audit: `INVOICE_ISSUED`.

## Case W.6: PATCH allow-list

```js
() => fetch("/api/organizations/<wipro-id>/billing-account/invoices/<invoiceId>", {
  method: "PATCH", credentials: "include",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({ status: "PAID" })
}).then(async r => ({ status: r.status, body: await r.json() }))
```

### Assertions
- `status === 400` or 403. The route at lines 100-120 explicitly does
  NOT allow PATCH → PAID (only the webhook can flip to PAID).
- DB invoice status unchanged.

Other transitions allowed via PATCH: DRAFT → ISSUED, ISSUED → VOID/CANCELLED.

## Case W.8: Webhook flips ISSUED → PAID

Forge the webhook payload with `notes.type = 'invoice_payment'` and
`notes.invoiceId = '<invoiceId>'`. POST to `/api/webhooks/razorpay`.

### Assertions
- DB: `OrganizationInvoice.status = 'PAID'`, `paidAt IS NOT NULL`.
- `SettlementLedgerEntry` row: `kind = 'INVOICE_PAID'`,
  `amountPaise = invoice.totalPaise`.
- Audit: `INVOICE_PAID`.
