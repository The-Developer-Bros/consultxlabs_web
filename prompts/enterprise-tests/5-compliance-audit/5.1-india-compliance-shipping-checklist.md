# 5-compliance-audit — India compliance shipping checklist

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).
> Apply the **fix-and-retest gate** when any case fails.

> This file is an end-to-end **assertion sweep** against the P0 items
> in `docs/compliance/15-india-compliance-shipping-checklist.md`. Each
> case here corresponds to one §1 row in that checklist and runs the
> minimal acceptance proof that the surface is live and behaving as
> documented.

**Surface(s) under test:** GST + TDS + MSME + DPDP + IRP + audit log
(end-to-end across the org-payout pipeline + invoice issuance).

**Case roster:**
1. **C.1** — GST CGST/SGST/IGST live (matches `3.4-gst-place-of-supply.md`)
2. **C.2** — TDS withholding live (matches `4.3-tds-withholding-on-org-payouts.md`)
3. **C.3** — MSME deadline live (matches `4.4-msme-deadline-on-org-payouts.md`)
4. **C.4** — DPDP consent gate (matches `1.4-dpdp-signup-consent-gate.md`)
5. **C.5** — DPDP breach 72h cron (matches `5.4-dpdp-breach-72h-cron.md`)
6. **C.6** — IRP uploader env-gated (matches `5.3-irp-uploader-and-irn-lifecycle.md`)
7. **C.7** — Per-org invoice numbering (matches `3.3-per-org-invoice-numbering.md`)
8. **C.8** — Audit log + ledger reconciliation (matches `5.2-audit-log-and-ledger-reconciliation.md`)

For each, this file runs **one** smoke case to confirm the surface is
alive and the assertion passes. Deep edge cases live in the linked
feature files. If any C.X case fails, run the linked file in full to
diagnose.

---

## Common preconditions

Use the seed cohort. The checklist runs sequentially; allow ~10 minutes
end-to-end.

---

## Case C.1: GST live

Issue an invoice for Wipro (KA buyer, KA supplier env default). Confirm
`cgstPaise + sgstPaise > 0` and `igstPaise = 0`. (1 minute.)

→ For full coverage: `3.4-gst-place-of-supply.md`.

---

## Case C.2: TDS live

Trigger a payout batch for `learnpro-academy`. Confirm
`tdsAmountPaise > 0` and `amountPaise === netPayoutPaise - tdsAmountPaise`.
(2 minutes.)

→ For full coverage: `4.3-tds-withholding-on-org-payouts.md`.

---

## Case C.3: MSME live

Set a fresh test host org to `msmeStatus = 'MICRO'`,
`msmeWrittenAgreementOnFile = false`. Trigger payout. Confirm
`mustPayByDate ≈ createdAt + 15 days`. (1 minute.)

→ For full coverage: `4.4-msme-deadline-on-org-payouts.md`.

---

## Case C.4: DPDP consent gate

Sign up a fresh user. Confirm 2 `ConsentArtifact` rows
(`PRIMARY_PROCESSING` + `STREAM_DATA_PROCESSING`) with valid SHA-256
hash. (1 minute.)

→ For full coverage: `1.4-dpdp-signup-consent-gate.md`.

---

## Case C.5: DPDP breach 72h cron

Insert a `DataBreach` 65 hours old. Run
`npx tsx jobs/compliance/databreach-deadline-alerts.ts`. Confirm warn
log fires. (1 minute.)

→ For full coverage: `5.4-dpdp-breach-72h-cron.md`.

---

## Case C.6: IRP uploader

Run `npx tsx jobs/compliance/irp-uploader.ts` with `CLEARTAX_API_KEY`
unset. Confirm rows still in `OrganizationInvoice` get a `FAILED`
`irpStatus` rather than a crash. (1 minute.)

→ For full coverage: `5.3-irp-uploader-and-irn-lifecycle.md`.

---

## Case C.7: Per-org invoice numbering

Issue an invoice for Wipro. Confirm `invoiceNumber` matches
`<PREFIX>-<FY>-<SEQ>` and `OrgInvoiceCounter` row exists. (1 minute.)

→ For full coverage: `3.3-per-org-invoice-numbering.md`.

---

## Case C.8: Audit + ledger

For each of cases C.1–C.7 above, verify the corresponding `OrgAuditLog`
row was emitted AND the three ledgers net consistently. The
`jobs/reconcile/reconcile-ledgers.ts` cron writes a
`LedgerReconciliationReport` row — run it after C.7 and assert the
report has `ok = true`. (2 minutes.)

→ For full coverage: `5.2-audit-log-and-ledger-reconciliation.md`.

---

## Cross-check against the shipping checklist

After all C.1–C.8 pass, sign off `docs/compliance/15-india-compliance-shipping-checklist.md`
§1 items as live. P1 items (Form 26Q quarterly returns, DSAR export
endpoints, in-app withdrawal UI, GSTIN registry verify, place-of-supply
B2C, HSN selection logic, invoice-fraud mitigation) are explicitly out
of scope and tracked in §2 of that doc.

If any C.X case fails: per the case-template gate, classify the fix
(TRIVIAL → apply + retest; NON-TRIVIAL → STOP + ASK). India compliance
fixes are **always** NON-TRIVIAL — every one of the surfaces touches
`lib/compliance/**` or `lib/payments/payouts/**` or a payment-gateway
script. ASK before applying.
