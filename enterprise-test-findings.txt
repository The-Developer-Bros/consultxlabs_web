[BUG] SSO.1/SSO button — BetterAuth crashes with 500 when the SAML cert stored in
  OrganizationSSOSettings.samlConfig is not a valid X.509 PEM certificate.
  Error: TypeError: Cannot read properties of undefined (reading 'metadata')
  Occurs in BetterAuth's SAML library at POST /api/auth/sign-in/sso.
  Two sub-issues:
    (a) The SSO provider creation API (POST /sso/providers) does NOT validate that
        the cert field is a valid PEM certificate. It accepts any string, including
        our fake "MIIBkTCB+wIJAJHoKtest1234567890==" which is not a real cert.
        FIX: Validate PEM format in createProviderSchema / samlConfigSchema.
    (b) BetterAuth's SSO sign-in route crashes with 500 + empty body instead of
        returning a 400 with a friendly error. The UI has no error handler for this
        case, so the user sees no feedback when SSO fails.
        FIX: Wrap POST /api/auth/sign-in/sso handler in try/catch, return 400/503
        with message "SSO configuration error — contact your IT administrator."
  Security note: attacker is still blocked (can't sign up: SSO_REQUIRED 403;
  can't complete SSO: crashes). But the crash is the wrong reason to be safe.
  Status: Non-trivial — involves BetterAuth internals. Cert validation is trivial (add regex/x509 check in samlConfigSchema).
