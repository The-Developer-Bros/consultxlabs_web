# Schema reference: the review tables

This page lists every column and index of `ConsultantReview`, `ConsultantReviewRevision`, `ScoringSnapshot`, the score columns on `ConsultantProfile`, and the review relation on `ModerationReport`, with the reasoning that is too long for a schema comment. Everything added by #1300 is nullable or defaulted, so nothing needs a backfill; the one non-additive change the design asks for is deferred and explained in [07-deployment-and-deferred-work.md](07-deployment-and-deferred-work.md).

## `ConsultantReview`

The table below lists the review row's columns.

| Column                                                                                          | Why it exists                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rating` (`SmallInt`), `reviewDescription?`                                                     | The live text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `consultantProfileId`, `consulteeProfileId`                                                     | The relationship the review is about. Both `Cascade`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `appointmentId?` (`SetNull`)                                                                    | Provenance, not subject (#705): which session prompted or last updated the review, which is what makes "verified booking" a fact rather than a claim. `SetNull` because tombstoning an appointment must not delete published consumer reviews. `NULL` means legacy; the API requires it.                                                                                                                                                                                                                                                                                                                            |
| `ratingUnitId?`                                                                                 | The group event key, `"webinar:<id>"` or `"class:<id>"`, and `NULL` on a one-to-one review. Not moved on edit, because reassigning it merges event buckets. See [02-two-track-scoring.md](02-two-track-scoring.md).                                                                                                                                                                                                                                                                                                                                                                                                 |
| `track?` (`ReviewTrack`)                                                                        | `ONE_TO_ONE` or `GROUP`. `NULL` is legacy and unclassifiable and contributes to neither published score. Adopted on the next write for the pair and never moved once set.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `revisionNo` (default 1)                                                                        | The version number of the live text and the allocator for the revision trail. See [03-edit-trail-and-disclosure.md](03-edit-trail-and-disclosure.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `editedAt?`                                                                                     | When the text last changed. `NULL` = never edited, which is the "Edited" badge's own predicate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `ratingCause?` (`RatingCause`)                                                                  | The reviewer's claim. See [04-rating-cause-and-aggregate-exclusion.md](04-rating-cause-and-aggregate-exclusion.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `excludedFromAggregateAt?`, `excludedReason?` (`VarChar(200)`), `excludedByUserId?` (`SetNull`) | The staff adjudication that removes the row from every aggregate while it keeps rendering. `excludedReason` is staff-internal and never enters the public projection.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `ratedSessionAt?`                                                                               | The session's clock for recency decay, stamped from the run anchor's `endsAt`. `NULL` = legacy or unbounded offline session; the recompute falls back to `createdAt`.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `replyBody?`, `repliedAt?`, `replyDeletedAt?`, `replyDeletedByUserId?` (`SetNull`)              | The consultant's right of reply (#705). Columns rather than a table, because there is one reply per review and every read of a review already loads the row. `replyDeletedAt` is separate from the review's own `deletedAt` so staff can remove an abusive reply without erasing the consumer review beneath it. `replyDeletedByUserId` (#1542) tells apart the consultant withdrawing their own reply from staff removing it: a `NULL` remover on a removed reply reads as moderation, so `PUT` refuses to let the consultant replace it with a 409, while the consultant may freely replace their own withdrawal. |
| `isAnonymous`                                                                                   | Display choice only. Authenticity never depends on it, because the review is welded to a paid, attended session either way; what it buys is candour from a consultee who wants to book this person again.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `deletedAt?`                                                                                    | `NULL` = live. Soft delete (#693); public reads and the recompute filter on it, staff surfaces do not.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `deletedByUserId?` (`SetNull`)                                                                  | Who removed it. The author may revive a row they withdrew themselves; nobody revives a moderation removal. `NULL` on a removed row means a live row or a legacy removal whose actor was never recorded, and a legacy removal therefore reads as moderation, which fails closed. `SetNull` never `Cascade`: a departed staff member must not delete the record of what they removed.                                                                                                                                                                                                                                 |
| `createdAt`, `updatedAt` (`@updatedAt`)                                                         | `updatedAt` moves on a reply and on removal too, so it cannot be read as "the review changed"; `editedAt` is that column.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

The table below lists the review row's unique and indexes.

| Index                                                       | Why it exists                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@@unique([consultantProfileId, consulteeProfileId])`       | One review per consultee per consultant. Deliberately **not** partial on `deletedAt`: a moderation-removed review must not free the slot for the same person to re-post it. `POST` maps a `P2002` here to a 409 the client turns into "update your review". #1549 widens the key to `(consultantProfileId, consulteeProfileId, track, ratingUnitId)`, not merely to add `track`: the group score counts **events**, so a per-relationship key could only ever hold one event's response, and a repeat webinar attendee's second review overwrote their first while staying in the first event's bucket. A 1:1 row has `ratingUnitId` `NULL`, so the wider key needs `NULLS NOT DISTINCT` and ships as a sidecar index rather than an `@@unique` in the schema, the same pattern #1554 prescribes for `AppointmentFeedback`. |
| `@@index([consultantProfileId, deletedAt, ratingUnitId])`   | Serves the score recompute's per-consultant scan. It is no longer a `groupBy`, because per-row recency decay cannot be expressed as a Prisma aggregate, so the recompute reads raw rows and the index's leading two columns serve the seek.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `@@index([appointmentId])`                                  | The `SetNull` scan on appointment tombstoning.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `@@index([consulteeProfileId])`                             | Explore's "trending" sort orders profiles by review count (#696), and the social-proof reads join through it. The unique already prefixes `consultantProfileId`, so no single-column index is needed for that side.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `@@index([excludedByUserId])`, `@@index([deletedByUserId])` | Postgres does not index a foreign key for you, and both are `SetNull`. `prisma.user.delete`, which the account-deletion route takes when no money history has to be retained, makes Postgres find every referencing row, so without these it would sequential-scan this table twice per removed staff account.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## `ReviewTrack` and `RatingCause`

`ReviewTrack` is `ONE_TO_ONE` or `GROUP`, with no `MIXED` value: a review lands in exactly one track, or in neither. `RatingCause` is listed in [04-rating-cause-and-aggregate-exclusion.md](04-rating-cause-and-aggregate-exclusion.md).

## `ConsultantReviewRevision`

One append-only row per superseded version of a review's text. The table below lists its columns and indexes.

| Column or index                             | Why it exists                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reviewId` (`Cascade`)                      | Was `Restrict`; #1542 re-points it to `Cascade` because `Restrict` sat beneath the `User` → `ConsulteeProfile` → `ConsultantReview` cascade and blocked account erasure with `P2003` for anyone who had ever edited a review. Deleting a review now takes its revision history with it.                                                                    |
| `revisionNo`                                | The version number this snapshot **was**, allocated from `ConsultantReview.revisionNo` inside the same transaction as the edit.                                                                                                                                                                                                                            |
| `rating` (`SmallInt`), `reviewDescription?` | The superseded values. `rating` is not nullable, because a review always had one.                                                                                                                                                                                                                                                                          |
| `supersededAt`                              | When this text stopped being the live text.                                                                                                                                                                                                                                                                                                                |
| `afterPublicReply` (default false)          | Whether the review had a live reply when the edit landed. Stored, not derived, because `repliedAt` is mutable; moderation context only.                                                                                                                                                                                                                    |
| `editorUserId?` (`SetNull`)                 | Who caused the supersession. `PUT`/`DELETE /api/user/reviews/[id]` are OWNER-ONLY on this branch, so this now only ever records the author; the column stays generic rather than renaming to `authorUserId` because a departed staff redaction still exists in rows from before #1542. `SetNull` because a revision must survive the account that made it. |
| `createdAt`                                 | There is no `updatedAt`. A row that is only ever inserted has nothing to update, and the column would invite a writer to try.                                                                                                                                                                                                                              |
| `@@unique([reviewId, revisionNo])`          | Two concurrent edits cannot both claim revision 3. This is the guard behind the allocator, not merely a shape assertion.                                                                                                                                                                                                                                   |
| `@@index([reviewId, supersededAt])`         | "This review's history, newest first", which is the public disclosure and the staff moderation surface. Its leftmost prefix also serves the `Cascade` delete's scan for this review's revisions, which Postgres does not index for you.                                                                                                                    |
| `@@index([editorUserId])`                   | `editorUserId` is a `SetNull` foreign key, so a user delete scans this table without it.                                                                                                                                                                                                                                                                   |

## `ScoringSnapshot`

One immutable row per scoring run. The table below lists its columns.

| Column or index                                                                                              | Why it exists                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `platformMeanOneToOne`, `platformMeanGroup`, `sampleCountOneToOne`, `sampleCountGroup`                       | The track priors: the mean each track is shrunk toward, and the corpus behind it. Data, pinned per run so one run is internally consistent.                                 |
| `priorWeight`, `halfLifeDays`, `minRatedClientsOneToOne`, `minRatedEventsGroup`, `minGroupResponsesPerEvent` | The parameters this run applied, copied from `SCORING_PARAMS` in `lib/reviews.ts` so a score published six months ago is still explainable after a constant moves.          |
| `computedAt`                                                                                                 | When the run happened. There is no `updatedAt`: a snapshot is inserted once and never edited.                                                                               |
| `@@index([computedAt])`                                                                                      | "The current snapshot" and "the snapshot in force on date X" are the only two reads, and a descending btree scan is as cheap as an ascending one, so one index serves both. |

## The score columns on `ConsultantProfile`

The table below lists the columns the recompute writes on the profile.

| Column or index                                                                                       | Why it exists                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `rating` (default 0)                                                                                  | The legacy raw mean over rating units. Internal and staff-facing; never the public number, because a 5.0 from one session must not outrank a 4.8 from two hundred in a `rating: "desc"` sort.                                                                                                                                                                                                                                                                                              |
| `publishedRating?`                                                                                    | The legacy blended published score, `NULL` below `MIN_RATED_UNITS_FOR_PUBLIC_SCORE` units. Still written so readers that have not moved to the tracks keep working.                                                                                                                                                                                                                                                                                                                        |
| `ratingUnitCount`, `reviewCount`                                                                      | The legacy denominator, and the display count that also retires the trending sort's `{ reviews: { _count: "desc" } }`, which counted soft-deleted rows because Prisma cannot filter a relation `_count` inside `orderBy`. `reviewCount` counts every **live** row (`deletedAt: null`), including one `excludedFromAggregateAt` has removed from the score; only the score arithmetic drops an excluded row, so "Reviews (N)" on the profile matches the number of cards actually rendered. |
| `ratingAggregatedAt?`                                                                                 | Stamped by every recompute. With recency decay a score drifts without new reviews, so this is the selector a scheduled recompute would use rather than a drift audit.                                                                                                                                                                                                                                                                                                                      |
| `publishedRatingOneToOne?`, `publishedRatingGroup?`                                                   | The two published scores. `NULL` = suppressed, exactly as `publishedRating` means it, and the conservative default that makes the columns correct with no backfill.                                                                                                                                                                                                                                                                                                                        |
| `ratedClientsOneToOne`, `ratedEventsGroup` (default 0)                                                | The denominators the suppression gate tests and the "based on N" display: distinct clients for 1:1, events with at least `MIN_GROUP_RESPONSES_PER_EVENT` responses for group.                                                                                                                                                                                                                                                                                                              |
| `rawRatingOneToOne?`, `rawRatingGroup?`                                                               | The undecayed, unshrunk means. Staff-facing diagnostic for "why is my score 4.1 when every review says 5".                                                                                                                                                                                                                                                                                                                                                                                 |
| `effectiveSampleOneToOne?`, `effectiveSampleGroup?`                                                   | The sum of the per-point decay weights; stale in exact lockstep with the score it explains.                                                                                                                                                                                                                                                                                                                                                                                                |
| `scoringSnapshotId?` (`SetNull`)                                                                      | Which run's priors and parameters produced the scores above. Same shape and argument as `Appointment.cancellationPolicyId`.                                                                                                                                                                                                                                                                                                                                                                |
| `@@index([publishedRating])`, `@@index([publishedRatingOneToOne])`, `@@index([publishedRatingGroup])` | Explore sorts on `publishedRating` with `nulls: "last"` today, and the two track indexes are for the same sort once it moves onto one track at a time. Two single-column indexes rather than a composite, because a composite cannot serve a sort on its trailing column.                                                                                                                                                                                                                  |
| `@@index([scoringSnapshotId])`                                                                        | Postgres does not index a foreign key for you; the `SetNull` scans by this.                                                                                                                                                                                                                                                                                                                                                                                                                |

## `ModerationReport.reviewId`

`reviewId?` is a real relation to `ConsultantReview` with `onDelete: SetNull`, and `@@index([reviewId])` serves the staff queue's "reports about this review" and the `SetNull` scan. The reasoning is in [05-moderation-and-reports.md](05-moderation-and-reports.md).
